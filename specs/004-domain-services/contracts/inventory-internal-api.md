# Inventory Internal API v1

**Provider**: Inventory service | **Consumer**: Checkout (completion saga and recovery) |
**Transport**: HTTP/1.1 JSON, internal network (port 8083) | **Java records**:
`service-contracts` → `edu.northeastern.cs6510.contracts.inventory.v1`

The public `GET /inventory/low-stock` route is also served by Inventory, through the gateway. Its
public shape is defined by the OpenAPI contract. The internal routes below are not exposed by the
gateway.

## Common rules

- **Idempotency key**: the path's `attemptId`, a UUID generated by Checkout and distinct from the
  transaction id. Every command may be repeated any number of times. A repeat returns the stored
  outcome and never applies a second stock effect.
- **Unknown outcome**: a client timeout means "unknown". The caller repeats the same command or
  queries with `GET`. It never issues a different command for the same attempt until the outcome
  is known, except for the documented `cancel` after `cancel-after` (research R8/R9).
- **Concurrency**: each command is one Inventory local transaction. It locks the reservation row
  first, then the affected positions in ascending SKU order, so it never deadlocks with another
  command in a cycle. Lock-wait or deadlock victims are retried by the server up to 3 times before
  returning `503`.
- **No expiry**: reservations never expire on their own. Release happens only through `cancel`.
- **Errors**: `{ "error": "...", "message": "..." }`.
- **Client budgets** (Checkout): 300 ms connect, 1,500 ms read, up to 3 attempts within the 5 s
  public deadline. Background recovery uses backoff of 250 ms × 2ⁿ, capped at 5 s.

## Reservation resource

```json
{
  "attemptId": "0192c3f4-…",
  "transactionId": "7b1e…",
  "state": "RESERVED",
  "lines": [
    { "sku": "SKU-000001", "requestedQuantity": 3, "reservedQuantity": 2 },
    { "sku": "SKU-000002", "requestedQuantity": 1, "reservedQuantity": 1 }
  ],
  "createdAt": "2026-10-24T12:00:00.000000Z",
  "resolvedAt": null
}
```

`state` ∈ `RESERVED | COMMITTED | RELEASED | CANCELLED`. The transitions are in
[data-model.md](../data-model.md#reservation-reservations-new-and-reservation-line-reservation_lines-new).

## `PUT /internal/v1/reservations/{attemptId}`: reserve

Request:

```json
{ "transactionId": "7b1e…", "lines": [ { "sku": "SKU-000001", "quantity": 3 }, { "sku": "SKU-000002", "quantity": 1 } ] }
```

Validation: 1–1,000 distinct SKUs, each `quantity ≥ 1`. Otherwise
`400 INVALID_RESERVATION_REQUEST`.

Behavior:
- **New id**: for each SKU, `reserved = min(quantity, physical_stock − reserved_stock)`, where a
  SKU without a position reserves 0. If Σ reserved > 0, the state is `RESERVED`. Otherwise the
  state is `RELEASED` and nothing is held.
- **Existing id**: returns the stored resource unchanged, whatever its state, including a
  `CANCELLED` tombstone, which reserves nothing.
- **Same id, different `lines`**: `409 RESERVATION_MISMATCH`. Checkout's attempt lines are
  immutable, so this indicates a bug.

Responses: `201` with the resource when created, `200` with the resource when it already existed.

## `POST /internal/v1/reservations/{attemptId}/commit`

| Current state | Response | Effect |
|---|---|---|
| `RESERVED` | `200`, state `COMMITTED` | Each line with reserved > 0 is queued as a sale. Shortly afterwards (about 100 ms), `physical_stock −= reserved` and `reserved_stock −= reserved` are applied and one `SALE` movement `(attempt_id, sku)` is written. The sale is final at the commit; until it is applied the units stay reserved, so availability is never overstated |
| `COMMITTED` | `200`, state `COMMITTED` | none (idempotent) |
| `RELEASED` / `CANCELLED` | `409 RESERVATION_NOT_COMMITTABLE`, body includes the resource | none |
| not found | `404 RESERVATION_NOT_FOUND` | none |

## `POST /internal/v1/reservations/{attemptId}/cancel`

| Current state | Response | Effect |
|---|---|---|
| `RESERVED` | `200`, state `RELEASED` | `reserved_stock −= reserved`. Physical stock unchanged |
| `RELEASED` / `CANCELLED` | `200`, same state | none |
| `COMMITTED` | `409 RESERVATION_COMMITTED`, body includes the resource | none. The caller must finalize, not compensate |
| not found | `200`, state `CANCELLED` (tombstone, no lines) | Guarantees that a late reserve with this id reserves nothing |

## `GET /internal/v1/reservations/{attemptId}`

`200` with the resource, or `404 RESERVATION_NOT_FOUND`. Used by recovery and operators. Never
mutates.

## `GET /inventory/low-stock?threshold={n}` (public route, owned here)

- Selects positions with `physical_stock < threshold`. The default threshold comes from
  configuration (`LOW_STOCK_THRESHOLD`, 10).
- Response follows the public `LowStockResponse`, with `name` taken from the name projection and
  `currentStock` = physical stock.
- `triggeredAt` is the time of the most recent `SALE` movement that took the SKU below the
  threshold. If there is no such movement, it is the response time.
- `503 SERVICE_UNAVAILABLE` if an alerted SKU has no projected name (amendment A6).

## Test-only provisioning

Controlled restocking for US1-4 and the measured-stock seed is done by
`deployment/provisioning/*.sql` executed with **Inventory's own credentials**. It adds the same
amount to `initial_stock` and `physical_stock` and writes a `PROVISION` movement. No HTTP
provisioning endpoint is exposed.
